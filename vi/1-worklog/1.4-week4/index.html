Worklog Tuần 4

Mục tiêu tuần 4:

  • Xây dựng backend và frontend cho trang thông tin cá nhân trên Smart Docs AI: xem/cập nhật thông tin, upload avatar, đổi mật khẩu — đồng bộ giữa Cognito và DynamoDB.
  • Thêm cơ chế tự phục hồi (self-healing) để profile bị thiếu trong DynamoDB luôn có thể tự tạo lại từ Cognito.
  • Thay nút “Đăng nhập bằng Google” (đang là placeholder) bằng luồng OAuth thật qua Cognito Hosted UI ở frontend.

Các công việc cần triển khai trong tuần này:

2- Rà soát cấu trúc backend của trang profile và xác định 4 API route cần có: GET /api/profile, PUT /api/profile/personal-info, PUT /api/profile/avatar, POST /api/profile/change-password
 + Xem lại các hàm trích xuất token mà mỗi route dùng (extract_user_id_from_token, extract_cognito_username_from_token, extract_claims_from_token) — đều decode thẳng payload JWT từ header Bearer mà không cần gọi lại Cognito, nhưng các lệnh admin_* phải dùng đúng Cognito Username thật (= email với user thường, Google_xxx với user liên kết Google), không được dùng sub		13/07/202613/07/2026
3- Triển khai flow lấy hồ sơ người dùng kèm cơ chế tự phục hồi:
 + get_user_profile(user_id): đọc thẳng item trong DynamoDB (smartdocai-user-profiles) theo user_id (Cognito sub)
 + ensure_user_profile(user_id): nếu chưa có item, gọi Cognito list_users với Filter=sub="{user_id}" (không dùng được admin_get_user(Username=user_id) vì pool này dùng email làm Username chứ không phải sub), lấy email/name/phone_number/birthdate từ attributes của user tìm được, rồi put_item kèm ConditionExpression=attribute_not_exists(user_id) để tránh ghi đè lên profile mà 1 request khác vừa tạo cùng lúc — bắt lỗi ConditionalCheckFailedException rồi đọc lại thay vì lỗi luôn
 + Gắn vào GET /api/profile		14/07/202614/07/2026
4- Xây dựng luồng cập nhật thông tin cá nhân (họ tên, email, số điện thoại, ngày sinh):
 + Validate: chặn field rỗng, regex check định dạng email, chuẩn hóa số điện thoại về E.164 qua normalize_phone() (số 0 đầu → +84) rồi regex check kết quả, regex check dob đúng định dạng YYYY-MM-DD
 + Pattern đồng bộ trong update_personal_info(): cập nhật Cognito trước qua admin_update_user_attributes (nguồn dữ liệu gốc) — nếu bước này lỗi thì dừng ngay, không đụng tới DynamoDB; chỉ khi Cognito thành công mới cập nhật DynamoDB (create_or_update_profile) như cache — nếu bước này lỗi thì chỉ log warning chứ không trả lỗi cho client, vì Cognito đã cập nhật thành công rồi (eventual consistency)
 + Gắn vào PUT /api/profile/personal-info, dùng extract_cognito_username_from_token (không dùng sub) để định danh user với Cognito		15/07/202615/07/2026AdminUpdateUserAttributes – Cognito
5- Thêm xử lý upload avatar và đổi mật khẩu:
 + update_avatar(): decode base64 (bỏ prefix data: nếu có), chặn nếu ảnh vượt quá 5MB; nếu ảnh sau decode dưới 300KB thì lưu base64 thẳng vào item DynamoDB, còn lớn hơn thì upload lên S3 tại avatars/{user_id}/{uuid}.jpg và chỉ lưu avatar_url trong DynamoDB (xóa field base64 cũ nếu có)
 + Ở frontend, thêm bước resizeImage() trước khi upload (resize canvas về chiều rộng 300px, chất lượng JPEG 0.7) để phần lớn avatar rơi vào nhánh lưu DynamoDB (<300KB) thay vì phải đẩy lên S3
 + change_password(): gọi admin_set_user_password(Permanent=True); chỉ bắt buộc nhập mật khẩu hiện tại nếu flag password_set của profile đang là true (để user chỉ đăng nhập Google có thể set mật khẩu lần đầu mà không cần nhập current)
 + Bắt buộc mật khẩu mới tối thiểu 6 ký tự, set password_set = true trong DynamoDB sau khi đổi thành công
 + Gắn vào POST /api/profile/change-password, route này đọc password_set qua ensure_user_profile() trước để quyết định có bắt nhập current_password hay không		16/07/202616/07/2026AdminSetUserPassword – Cognito
6- Code luồng “Đăng nhập bằng Google” ở frontend:
 + Thêm file src/api/cognitoOAuth.js gồm getGoogleLoginUrl() (tạo URL redirect sang Cognito Hosted UI kèm identity_provider=Google), exchangeCodeForTokens() (đổi authorization code lấy token thật tại /oauth2/token), decodeJwtPayload() (giải mã claim JWT phía client chỉ để hiển thị UI, không dùng để verify), và persistCognitoSession() (ghi token vào sessionStorage đúng định dạng key mà amazon-cognito-identity-js đang dùng, để ProtectedRoute, axiosConfig dùng lại được ngay không cần sửa gì)
 + Thêm src/features/auth/pages/GoogleCallbackPage.jsx xử lý route /auth/callback: đọc code/error từ query string, chặn chạy 2 lần do React StrictMode bằng useRef, dispatch đăng nhập rồi điều hướng vào /app nếu thành công hoặc quay lại /login kèm toast lỗi nếu thất bại
 + Thêm async thunk loginWithGoogleCode cùng các case pending/fulfilled/rejected vào authSlice.js
 + Nối nút Google trong LoginForm.jsx sang redirect qua getGoogleLoginUrl() thay vì hiện toast “đang phát triển” như trước
 + Khai báo route /auth/callback mới trong App.jsx		17/07/202617/07/2026Using social identity providers with a user pool – Cognito
